The driver contracts of `@novastarter/memory` are now `KvDriver`, `CacheDriver`, `BusDriver` and `LimiterDriver` — the `Driver` suffix every other subsystem uses — so rename the `Kv`, `Cache`, `Bus` and `Limiter` types in calling code; `KvDriverLocal` and `CacheDriverLocal` can now be constructed without a config object. `CacheDriverMulti` gains `close()`, which quits the subscriber connection its bus opened, and surfaces a failed subscription on the first write instead of as an unhandled rejection; `KvDriverRedis.increment` and `setMax` give the key the configured `ttl` like `set` does, where a key they created used to live for good, and an `INCRBY` that fails inside that transaction throws instead of answering `0`; locks live under a namespace of their own (`<namespace>-locks`), so locking a key and storing a value under it no longer collide — a lock on a stored key used to fail after the retry budget, and a value written under a held lock used to break its release — and `clear()` leaves held locks alone; Redlock follows the client into its database (`redis://host/2`) instead of always locking in database 0, and a `lockTimeout` between 200 and 600 ms no longer makes `usingLock` throw; `KvDriverLocal` gives up waiting for a lock after its own `lockTimeout` (5 s by default), and the Redis store waits about its `lockTimeout` for a busy lock too, where it used to retry for a fixed 5 s; `lockTimeout` under 200 ms or past what a timer can hold (Redlock renews a held lock ahead of its expiry and needs 100 ms of headroom), a local `lockTimeout` a timer cannot hold, and a client on a Redis database above 15 — where Redlock cannot lock — are refused at construction; `release()` of a lock that had already expired fails at once instead of retrying for the whole budget and a second `release()` of a handle is a no-op on both backends; the local bus hands subscribers a serialised copy of the payload, as the Redis bus does, and treats a channel named like an `Object.prototype` member as a channel; `CacheDriverMulti` writes L2 before L1, so a Redis that refuses the write leaves nothing in L1 that only this process would serve; the Redis bus hands messages to subscribers in the order Redis sent them even when one needs decompressing; a lock from `KvDriverRedis.acquireLock` can be extended more than once, where the second `extend()` used to throw "already expired" because the handle kept the lock object Redlock had invalidated; `KvDriverRedis.setMax` answers `false` for a value that was not stored (the Lua script answered `false`, which Redis turns into `nil`, so it used to read as `true`), `clear()` skips the empty batches `SCAN` may answer with, and the unused `release` command is no longer defined on the client. `KvDriverLocal` locks for real — one holder per key at a time within the process, where `acquireLock` used to hand out a no-op — and a bus handler may be async: a subscriber that throws or rejects is logged through `@novastarter/logger` (now a dependency) instead of being swallowed by the local bus or left as an unhandled rejection by the Redis one — once per subscriber and channel until it succeeds there again, so a broken one neither floods the log nor, when the log itself travels over the bus, feeds itself. The Redis bus logs a message it cannot decode instead of dying on an unhandled rejection, and a failed `SUBSCRIBE` leaves no half-registered channel behind — every `subscribe()` that joined while it was under way learns of the failure too — so a retry subscribes for real; `CacheDriverMulti` subscribes before it writes either level and subscribes again on the next write after a failed subscription, instead of leaving a key in L1 that no invalidation can reach or staying dead for the rest of the process, and refuses a write after `close()` for the same reason. `KvDriverLocal.setMax` stores any number on a missing key, as the Redis script does, where it used to refuse a zero or negative one.
